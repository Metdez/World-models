# 12-03 PLAN — Race Engineer for driving + drive analytics

**Objective.** While the visitor drives (or just drove), "Ask the engineer" answers from what actually happened: the
detected drive event with values captured at its moment, the inputs just before it, and the current suspension, aids,
surface and station. The model explains DETECTED events only and quotes only payload numbers (unit-aware check). Driving
fact cards; every comparative claim pinned by a test to sim-core values. Rule-based answer for every event kind (zero
neurons). Event chips. Anonymous `drive-session` / `station-visit` analytics. Contracts unchanged (ARCH-M2 §12.4–12.5).

**Owned files.** `worker/engineer/**`, `worker/routes/engineer.ts`, `worker/schemas/engineer.ts`, `worker/routes/event.ts`,
`worker/schemas/event.ts`, `src/features/engineer/**`, `src/features/analytics/**`, `tests/worker/engineer*.test.ts`,
`tests/worker/event.test.ts`, `tests/features/analytics.test.ts`, `tests/fixtures/12-03-*`, `tests/e2e/12-03-engineer.spec.ts`.

## Tasks
1. **Worker.** `schemas/engineer.ts` accepts the optional `drive` block (strict, bounded, digit-free labels).
   `facts.ts` driving cards (`DRIVE_COMMON`, `DRIVE_COMPARE`, per-type `DRIVE_FACTS`): tyre grip vs load, weight transfer,
   lift-off rotation, understeer/oversteer, lock-up + ABS, traction, stability, compliance steer (what the multi-link
   rear does here), measured per-type differences (strut ≈ wishbone), launch/stopping figures as model outputs.
   `prompt.ts` DRIVE section + rules (explain DETECTED only; none → what telemetry shows). `numbers.ts` unit-aware
   (km/h, g, degrees, deg/s, mm, N, %, s match only payload values with that unit). `fallback.ts` (+ byte-identical
   `rules.ts`) shared drive-event labels and one answer per event kind + driving glossary. Route: drive tools exclude
   `jump_to_section`. Tests: schema, number check, fallback per kind, recorded real lift-off answer parsed,
   `engineer-drive-facts.test.ts` pins every driving claim to sim-core runs (09-04 fixtures).
2. **Client + analytics + e2e.** Snapshot ring gains drive fields; the engineer keeps the last detected event (bus
   `drive:event`, `sim:event` liftoff/bump-stop, swaps while driving) with a captured snapshot + inputs 0.5 s before;
   payload `drive` block + derived pre-event inputs; "Why did it do that?" uses it within 5 s; 2–3 event chips
   (panel only, no pop-ups); seek actions skipped outside Auto. Analytics tracker: `drive-session` on leaving Manual
   (whole seconds, ≥ 5 s), `station-visit` on station-zone entry while driving (m/s rounded); DNT/GPC and e2e off as
   before. e2e with `page.route` mock on a private build.
3. **Live evaluation** (≤ 25 model calls, 6–8 driving questions) via `engineer-live.test.ts`; deploy only if needed
   (private worktree, health version check). SUMMARY.
